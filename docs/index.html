🎯项目解决什么问题

中国各级足球赛事数据长期分散在不同站点；现场上座更是「官方一套、媒体一套、社区一套」。

赛事数据分散

中超、中甲、中乙、中冠、足协杯、女超等赛事分布在不同站点；需要统一抓取并归一化到同一数据模型。

上座来源不统一

官方战报、俱乐部公告、媒体报道、社区估算……同一场比赛常出现多个差异较大的数据。

可信度差异大

按「官方 → 俱乐部 → 媒体 → 社交 → 人工」给来源打分，UI 始终展示最可信值，估算数据单独标记。

可追溯 / 可修正

所有人工修改写入 audit log；含「预计」「或将」「可能」的数据自动降权，避免被当成 confirmed。

🛡️数据可信度机制

每一条 attendance 记录都附带元数据，便于交叉核对、修正与回溯。

每条记录保留的字段

  • sourceUrl可点击的原文链接，方便复核
  • sourceType官方联赛 / 俱乐部 / 媒体 / 社交 / 人工 / 未知
  • rawTextExcerpt新闻或战报原文片段，留底比对
  • collectedAt数据采集时间；UI 显示 Asia/Shanghai 时区
  • confidenceScore0..1 数值；按来源、估算、不确定性折扣
  • estimated「超过 4 万人」「近 3 万」等估算数据强制标记
  • verified人工核验过的记录，自动提升至高可信

可信度等级

  • 高可信
    ≥ 0.90
    联赛/足协官方、俱乐部官方公告，或人工已核验
  • 中高可信
    0.70 – 0.89
    俱乐部官方、权威媒体的具体报道
  • 待核验
    0.50 – 0.69
    社交媒体、社区估算、人工未核验
  • 低可信
    < 0.50
    未知或质量不明的来源
含「预计」「或将」「可能」等不确定描述的数据不会被当作 confirmed attendance，会自动降权并写入备注。

💻开发者快速开始

想运行完整服务（包括 API、抓取、人工补录）？按以下步骤本地启动。

🛠 技术栈 · 项目结构 · 命令
技术栈
Next.js 14 (App Router) · TypeScript · Tailwind CSS · Prisma · PostgreSQL · Recharts · Cheerio · Vitest
命令
# 1. 克隆 + 安装
git clone https://github.com/timkok/china-league.git
cd china-league
npm install

# 2. 配置数据库
cp .env.example .env
# 将 DATABASE_URL 指向你的 PostgreSQL 实例

# 3. 初始化数据库（含示例数据）
npx prisma migrate dev --name init
npm run db:seed

# 4. 启动开发服务器
npm run dev      # → http://localhost:3000
npm test         # 单元测试（29+ tests）
npm run build    # 生产构建
REST API（本地运行时可用）
  • GET /api/matches
  • GET /api/matches/:id
  • POST /api/attendance
  • PATCH /api/attendance/:id/select
  • GET /api/attendance/missing
  • POST /api/crawl/run
  • GET /api/stats/competitions
  • GET /api/stats/teams
数据模型核心表
Competition · Season · Team · TeamAlias · Venue · Match · AttendanceRecord · Source · CrawlJob · AuditLog

⚠️ 使用注意

  • 本页是 静态预览，所有数字来自 seed 示例数据；写操作 / 抓取 / 数据库需要本地或服务端启动 Next.js 应用。
  • 抓取请遵守目标网站的 robots.txt 与服务条款；默认 User-Agent 含联系方式、最小请求间隔 2 秒。
  • 估算数据（如「超过 4 万人」）始终带「估算」标签，请勿当作官方精确数据用于商业分析。
  • 多源差异（同场比赛有多条不同上座数据）在比赛详情页显式高亮，便于人工核实。
数据来源以官方发布为准，估算数据仅供参考。时区：Asia/Shanghai。
